# Event Flow

Event publishing and registration with versioned forms, application review and
admission, staff permissions, Tickets and Attendance, and printable Badges.
Organizers can export CSV data, export/import Event templates, and manage
Communications with frozen history and delivery status visibility.
See [PRODUCT.md](PRODUCT.md) for implemented capabilities and [DOMAIN.md](DOMAIN.md)
for domain invariants.

## Stack

- Next.js 16.3.6 App Router, React 19.3.0, TypeScript.
- Material UI 9.4 with the official Next.js App Router integration and Emotion.
- PostgreSQL 18, Prisma ORM/Client 7.10.0, `@prisma/adapter-pg` and `pg`.
- Better Auth 1.7.6 email/password authentication.
- Zod validation, Temporal for timezone-aware event input, Nodemailer SMTP.
- Biome for linting/formatting; Docker Compose for PostgreSQL and Mailpit only.

## Requirements

Use Node.js 24 (`.node-version` and `engines`) and pnpm 11.23.0
(`packageManager`), plus Docker with Compose. Application and CLI
tooling run on the host. The Railway image pins Node.js 24.21.0. The production build fetches Google Fonts and needs
network access.

## Local setup

```bash
pnpm install
# For a new checkout only; preserve an existing .env.
cp .env.example .env
```

Before starting services, set `POSTGRES_PASSWORD` for the local database and
populate `BETTER_AUTH_SECRET` with a value generated by `openssl rand -base64 32`.
The auth secret must contain at least 32 characters. Also populate the required
`TICKET_CREDENTIAL_ENCRYPTION_KEY` with 32 random bytes encoded base64url (command
in `.env.example`). Generate it once, preserve it across restarts/deployments and
back it up securely outside the database. Do not reuse the auth secret. Existing
Ticket envelopes cannot be recovered without this key. Keep `.env` untracked.

### Fresh database

For a new, empty PostgreSQL 18 database, apply the complete migration history:

```bash
pnpm infra:up
pnpm exec prisma migrate deploy
pnpm db:generate
pnpm db:check
pnpm dev
```

There are no backfill, cutover or seed steps. Create users and Events through the UI.

Open the configured `BETTER_AUTH_URL`, initially `http://localhost:3000`, and use
that origin for authentication. To also use another address, set
`BETTER_AUTH_TRUSTED_ORIGINS` to a comma-separated list of additional exact HTTP(S)
origins (no paths, wildcards or trailing slashes), then restart the server. For
phone and laptop testing, use the LAN IP in `BETTER_AUTH_URL` and
`BETTER_AUTH_TRUSTED_ORIGINS=http://localhost:3000`. Better Auth and the theme/locale
APIs accept both. Email/public links keep the canonical `BETTER_AUTH_URL`; cookies
and sign-in sessions remain separate per hostname. `allowedDevOrigins` in Next.js
is an independent development-server setting. Prisma's generated client lives in
ignored `generated/prisma/`; generate it after installing or changing the schema.
Restart a running Next.js server after client regeneration/schema changes.

`prisma.config.ts` loads environment through `@next/env`; `lib/env.ts` validates
settings. `lib/prisma.ts` is the shared server-only client. DATABASE_URL expands
from the POSTGRES variables in `.env.example`; use a URL-safe local password or
percent-encode credentials when constructing a URL.

The PostgreSQL 18 migration history starts with `20261011030000_baseline` and
continues with incremental migrations for the current schema. Apply the complete
history with `prisma migrate deploy`; do not edit applied migrations. Custom SQL
CHECK constraints complement Prisma-managed keys and indexes; Prisma schema drift
alone does not verify those CHECK constraints.

Consolidating applied migrations or resetting disposable local DB/media requires
separate explicit approval. Neither is an upgrade strategy for persistent
production/staging data. There is no seed or demo data.

These are the scripts currently defined in package.json:

| Command | Purpose |
| --- | --- |
| `pnpm dev` | Run the development application |
| `pnpm build` | Generate Prisma Client, then build the production application |
| `pnpm start` | Run production with bounded HTTP/outbox/listener shutdown |
| `pnpm db:deploy` | Apply production migrations separately from build/start |
| `pnpm lint` | Run Biome checks without writing fixes |
| `pnpm format` | Format files with Biome; writes changes |
| `pnpm infra:up` | Start PostgreSQL/Mailpit and wait for healthchecks |
| `pnpm infra:down` | Stop/remove service containers; preserve database volume |
| `pnpm infra:status` | Show Compose service status |
| `pnpm db:migrate` | Run local `prisma migrate dev` |
| `pnpm db:generate` | Generate Prisma Client |
| `pnpm db:studio` | Open Prisma Studio |
| `pnpm db:check` | Check migration/schema alignment, then current domain integrity in a read-only RepeatableRead snapshot; report aggregate violations without private data |
| `pnpm media:cleanup` | Explicitly collect expired/unreferenced media and reconcile generated orphan files; writes to DB and the configured media directory |

`db:check` first checks the migration ledger against repository migration names and
checksums, rejecting missing history, pending, failed, unexpected, duplicate or
altered migrations. It then runs read-only Prisma datasource-to-schema comparison;
drift or an unavailable comparison stops the command before domain queries. This
preflight needs the installed Prisma CLI and checks Prisma-managed schema objects,
not custom SQL CHECK definitions. It never applies migrations or uses a shadow DB.

After preflight, `db:check` covers Application/Registration correspondence, PRIMARY
cardinality and identity, party activity, Ticket lifecycle, QR/MANUAL Attendance, current publication
references, and Communication/Outbox counts, types, normalized addresses, required
digests, strict contexts and every frozen delivery payload. JSON contexts are read in bounded keyset pages.
It also checks media ownership/references. Invalid EventSnapshot contracts, invalid
READY media manifests and revision cover-reference/variant mismatches have separate
aggregate categories. Cover comparisons require a valid snapshot; variant comparison
also requires a valid manifest, so malformed JSON is not mislabeled as a mismatch.
Every Outbox row requires a Communication and a valid frozen locale; application
receipt payloads require their Application ID. Snapshot/template readers accept only
the current Markdown-only EventSnapshot/EventTemplate contracts.
An empty database passes with an explicit zero-data-coverage message. Failures
exit nonzero; the command never repairs rows, decrypts credentials or sends mail.

Additional validation commands (CLI invocations, not package scripts):

```bash
pnpm exec prisma validate
pnpm exec prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --exit-code
pnpm exec tsc --noEmit
git diff --check
```

## Authentication development

Register at `/register` with a name, email, and 10–128 character password. Open the
verification link in Mailpit; links expire after one hour. Verification signs the
user in and returns to a safe local `returnTo` destination or `/account`.
Successful sign-in has the same default destination.

An unverified sign-in leads to `/verify-email`; it does not automatically send
another email. Use **Resend verification email** there. Resend has a 60-second UI
cooldown and a server limit of one request per 60 seconds for the endpoint's
rate-limit bucket. SMTP sending is awaited, and failures are reported. Existing
account registration receives a generic response, not another account or an
automatic resend; use the verification screen to request another link.

Sessions last seven days and refresh after one day through Better Auth endpoints;
server session lookups bypass cookie caching. `/account` supports name editing;
email is read-only. Organizer activation is a separate **Become an organizer**
action. Auth or onboarding GET requests do not create OrganizerProfile.

### Google OAuth

Google is optional. Set both `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` for a
Google OAuth **Web application** client, then restart the server. Neither value
is exposed in client props; never commit the secret. Leaving both empty preserves
email/password authentication and hides Google buttons on the auth screens.
Configuring only one fails environment validation.

Apply `20261011180000_account_provider_identity_unique` with
`pnpm exec prisma migrate deploy`, then regenerate the client with `pnpm db:generate`.
It adds PostgreSQL uniqueness for Account `(providerId, accountId)` without
rewriting the baseline or changing rows. Check for duplicate pairs first; if any
exist, stop for explicit data-remediation approval. Do not delete or merge them
automatically. PostgreSQL rejects conflicting concurrent OAuth inserts. With
Better Auth 1.7.6, the losing manual-link callback returns HTTP 500 on this
unique conflict; retrying the connection resolves the existing provider identity.

Configure the exact authorized redirect URI in Google Cloud Console:
`<BETTER_AUTH_URL>/api/auth/callback/google` (for local development,
`http://localhost:3000/api/auth/callback/google`). Use the canonical origin for
Google flows so session/state cookies remain on the same host. Configure the
consent screen and test users while the Google app is in testing; use HTTPS for
deployment. Only the native identity/profile/email scopes are requested.

Existing email collisions require signing in first and connecting Google from
`/account/profile`; no automatic merging is enabled. Select a Google account with
the same email. Profile supports disconnecting Google only while a password login
remains. A Google-only account cannot disconnect its only login method. Native
fresh-session failures require signing out and signing in again. The profile image
loads directly from its URL with initials on failure, without server-side storage.

Acceptance with real credentials must cover new/returning Google users, existing
verified and unverified email collisions, cancellation/retry, same-email manual
linking, an identity owned by another User, session expiry/account switches during
OAuth, unlink protection and email/password regression. Check avatar load failure,
all five locales and desktop/mobile layouts. Simulated provider checks do not
establish a real Google consent/callback result.

## Historical credentials

A missing historical Ticket is a corruption/investigation case, never a reason to
generate a replacement credential. Preserve the Ticket encryption key while its
data is retained; protect database and encryption-key backups separately when
retaining data. The disposable development baseline reset does not require backups.
Anonymous Ticket links now use browser fragments and a protected POST exchange,
followed by a path-scoped two-hour HttpOnly session. Legacy path-based bearer links
are removed; redirects cannot prevent ingress logs recording the first request.
Inspect retained environments before cutover. The local DEPLOY-2 preflight found
zero Tickets, anonymous approval deliveries and Mailpit messages. Do not assume
this proves another environment has no old links. Never log exchange bodies,
cookies, fragments or private email content; disable provider click/open tracking.

## Private Event media (29A)

Media operations require MEDIA_STORAGE_ROOT: an existing absolute persistent
directory owned by the application OS user, mode 0700, outside Git checkouts,
public/, .next/ and temporary directories. The full ancestor chain must be owned by
root or the application OS user, with no group/other write permissions or symlinks.
Provisioning must also exclude write-granting ACLs and untrusted mounts. Root and
same-UID processes are trusted not to replace paths during operations: Node's
portable path APIs do not provide universal TOCTOU protection. POSIX is required.
For example, create a dedicated directory under your Mac's Application Support:

```bash
mkdir -p "$HOME/Library/Application Support/Event Flow/media"
chmod 700 "$HOME/Library/Application Support/Event Flow/media"
```

Set its expanded absolute path in local `.env` (not a literal `$HOME`). Existing
non-media commands do not require this optional configuration; media operations
fail closed if it is missing/unsafe. The application does not create the storage
root or silently fall back to temporary/public directories. Files use opaque keys,
0600 permissions, atomic create-only publication and no-follow reads. Never mount
this directory as static web content. Provision the root during local/deployment
setup; upload handlers never create or substitute the root themselves.

The existing Event editor uses the POST/PUT/GET contracts documented in DOMAIN.md.
The public landing page and SEO are implemented in 29C, with final UX polish in 29D.
POST accepts raw JPEG/PNG/WebP bytes, not multipart or remote URLs. The server checks
Origin against BETTER_AUTH_URL and verifies OWNER scope. Input limits are 5 MiB,
4096 × 4096, one frame and two process-local operations. A new upload is refused
when the owner already has >=10 pending assets. Detach remains allowed and can
raise that count above ten; later uploads remain blocked while the count is >=10.
Input buffering uses one allocation capped at 5 MiB, independent of chunk count.
Sharp is a direct native dependency; install its platform binaries in the runtime
image. Original bytes/filenames/EXIF are not retained. Four immutable normalized
variants are stored, with fixed-size endpoints bypassing the Next.js optimizer.

Run `pnpm media:cleanup` deliberately against the intended DB/storage pair. It
expires incomplete uploads after 24 hours and unreferenced READY assets after seven
days. Draft and historical revision references always prevent deletion. Interrupted
deletions and generated orphan/temp files are recovered on subsequent invocations.
Each run selects at most 100 eligible DB candidates and attempts at most 100 orphan
file deletions (at most 500 file unlinks including four variants per DB candidate).
Known variants are removed directly; orphan reconciliation streams directory entries
with constant memory. Filesystem traversal/reference lookups remain O(F) and are not
strictly time-bounded; this is an accepted v1 limitation. `deleted` counts rows this
collector actually deleted; `orphans` counts files actually unlinked. Rerun while a
budget flag is true; a flag signals budget exhaustion, not guaranteed remaining work.
Failed DELETING rows retry; persistent failures must be repaired by the operator.
Existing Event assets require this explicit maintenance. Temporary creation covers
and aged orphan files also have a runtime startup/15-minute sweep with the same
candidate/deletion budgets. Monitor disk usage and invoke maintenance regularly.
Never point two unrelated databases at the same media root.

Back up the database and all referenced immutable variants together. A database-only
restore cannot recover cover files. Keep local storage on a persistent volume across
restarts/redeployments; ephemeral/serverless filesystems are unsupported. Multiple
instances need a shared private backend and an appropriate processing-resource budget.
Future S3 support can implement the small storage adapter and migrate internal
backend/key locators after verifying checksums. It must retain asset IDs, immutable
bytes and historical references; public DTOs/URLs must remain independent of storage.
No cloud integration is present; the SQL backend CHECK currently permits LOCAL only.

EventSnapshot is the only supported serialized publication/history format.
Template Export, Import and Duplicate use EventTemplate, preserving rich configuration
and explicitly omitting cover images. Both contracts are unversioned and strictly
validate the current shape, without compatibility readers or converters.

## Rich Event authoring and EventTemplate (29B)

Create, Edit, Import Review and Duplicate Review share a full-page, eight-tab
workspace editor (plus Additional settings for Import/Duplicate Review) and the atomic create path. Edit saves stay open; successful Create
opens the new editor. Preview opens the saved draft in a separate tab. Cover saves
remain independent, and app navigation asks before discarding unsaved changes. Descriptions use Markdown (including ordinary text), with optional
physical/online/hybrid location, up to 100 ordered agenda entries and explicitly
authored public organizer information. Markdown uses one restricted react-markdown
renderer for client preview and OWNER Event Preview: no HTML, images or MDX; only
absolute HTTP(S) links without credentials. Markdown is the only description format
in workspace, publication, templates and metadata; obsolete template fields are rejected.

Untouched agenda instants retain seconds/milliseconds, including ambiguous local
hours imported as exact UTC instants. Title edits/reordering preserve those instants;
edited/new local times reject DST gaps/folds. Changing timezone reinterprets local
times; changing Event dates does not shift the agenda. Invalid order/range is shown
inline. Event Edit obtains preserved instants from the version-checked locked row.

For existing Events, select a file, Upload, inspect the normalized preview and
Save cover. Cover and Event saves exclude each other. Only a successful cover
response advances the form token, preserving other unsaved edits. Replaced or
abandoned uploads remain tracked for the existing explicit cleanup lifecycle.
Create/Import/Duplicate can prepare a new private temporary cover before the Event
exists. Uploads belong to the verified organizer and expire after 24 hours. Atomic
creation attaches the prepared cover and saves a request-key retry receipt together.

Export downloads `-template.json`. EventTemplate includes rich configuration and an explicit
cover status NONE/OMITTED; no asset identity, storage locator or bytes are included.
The Export menu and Import/Duplicate Review explain omission. Import rejects
unknown fields. Source covers are never copied; a new Event has a cover only when
a newly prepared cover is explicitly included during creation.

OWNER Preview reads the draft workspace through EventSnapshot. Public pages still
read only the published revision; publish/republish is required to expose changes.
Overview and Staff projections remain operational. The media foundation (29A),
rich authoring (29B), public landing/SEO (29C), and UX/integration polish (29D)
are implemented and accepted.

## Localization development

`next-intl` is configured without locale routing or middleware. Existing links and
paths remain unchanged. The baseline includes User.uiLocale and User.uiMode.
Apply the baseline using `pnpm exec prisma migrate deploy`, generate the client
with `pnpm db:generate`, and restart the server after schema/client changes.

- Request configuration: `lib/i18n/request.ts` (account → cookie → browser → en).
- Dictionaries: `lib/i18n/messages/{shell,locale,validation,auth,events,landing,email}/{en,de,pl,uk,ru}.json`.
  English is merged per key before rendering. Add new features to the loader.
- Server: `await getTranslations("shell")`; Client: `useTranslations("shell")`.
  Use a client consumer for text that must change immediately without refreshing
  forms. `ShellText`, `AuthText` and `EventText` bridge labels in server-owned
  layouts and retained notifications. `InlineDateTime` renders compact Event
  timestamps with the active locale and the supplied Event timezone.
- ICU validation pattern: return `{code: "maxLength", values: {count: 200}}` with
  the field path; render `t(issue.code, issue.values)`. Store identifiers rather
  than translated strings. Do not change global Zod error maps per request.
- Dates: `useFormatter` / `getFormatter`, always supplying Event timezone for
  Event instants. Never reinterpret stored dates when changing UI language.
- Background work: `createBackgroundTranslator(explicitPreference)` works without
  a request. Email rendering uses it with each delivery’s frozen recipient locale (I18N-D).

Optional native build scripts introduced transitively by next-intl (`@swc/core`
and `@parcel/watcher`) are disabled; the application uses neither optional feature.

Appearance uses `User.uiMode` (light/dark/system, nullable) with account → cookie →
system priority. `lib/ui-preferences.ts` resolves both initial preferences using
the normal session reader and one request-cached User query. The MUI provider
disables localStorage persistence; old MUI-only settings are not imported.
System follows each device's OS without saving the computed light/dark result.

Preferences use SSR initialization and local client state. Locale loads messages,
sends PUT, then updates next-intl context. Theme sends PUT, then calls MUI setMode.
The existing `/api/preferences/locale` and `/api/preferences/mode` routes support
PUT only; there are no confirmation GETs, identity tokens or reconciliation loops.
Failed saves preserve the active selection and show a retryable translated error.

External changes appear after full reload. Successful authentication transitions
load a new document, while preference switching preserves URLs and unsaved forms.
Writes target only the request's authenticated User; stale tabs can save to the
currently signed-in account. Normal Better Auth session behavior is retained.
See PRODUCT.md and DOMAIN.md for the accepted V0 consistency limitations.

## Event language (I18N-B)

The current baseline includes required Event.language (en/de/pl/uk/ru) without a
database default. Manual Create captures the organizer's active UI locale once;
explicit edits and template language take precedence thereafter. UI preferences
and Event language are independent.

EventSnapshot and EventTemplate require language and have no format version fields.
Missing/unsupported language and unknown fields are rejected without conversion.
The explicitly authorized pre-release consolidation replaces the local migration
ledger with `20261011030000_baseline`, preserving authentication/organizer rows.
It does not require deleting Docker volumes, Mailpit or the media directory.
Existing installations with removed migration history need an explicitly approved
local reset; do not apply this consolidation to retained production data.

`/e?language=de` filters by published Event language independently of UI locale.
Omitting language selects all; unsupported/repeated values also select all.
Template export/import/duplicate retain the Event language and exact dates.

The catalog also provides immediate, case-insensitive published-title search,
combined with the language filter in the same field sizing/grid as the organizer dashboard.

## Railway Hobby deployment (DEPLOY-2)

Prepared for one always-on service with PostgreSQL 18 and a persistent volume;
no Redis, worker, cron or replacement queue. This repository does not deploy itself.
`Dockerfile` retains Prisma CLI and operational scripts. `railway.json` sets the
separate pre-deploy migration command, `/api/health`, restart policy and 75-second
draining period. Startup provisions media at runtime, then drops root to UID/GID
1000 before serving HTTP. A small documented Next.js custom server is required to
coordinate HTTP, embedded dispatcher and listener shutdown; no standalone bundle.

Configure the Railway service with one replica, sleeping/serverless disabled,
a volume mounted at `/data`, and a free generated HTTPS domain. Attached volumes
imply brief deployment downtime; schedule releases outside check-in periods.
Do not set a start-command override: the image CMD provisions the volume. The
pre-deploy command runs without that volume and only applies migrations.

Required runtime variables (all server-side; never NEXT_PUBLIC):

| Variable | Production value |
| --- | --- |
| DATABASE_URL | Direct private PostgreSQL 18 URL from the database service; no public proxy or transaction pooler |
| DATABASE_POOL_MAX | `5`; allow two additional listener connections and migration/admin headroom |
| BETTER_AUTH_URL | `https://<service>.up.railway.app`, exact origin without trailing slash |
| BETTER_AUTH_TRUSTED_ORIGINS | Empty unless additional exact origins are intentionally supported |
| BETTER_AUTH_SECRET | Stable random secret, at least 32 characters |
| TICKET_CREDENTIAL_ENCRYPTION_KEY | Stable canonical base64url 32-byte key; preserve with retained Tickets |
| EMAIL_TRANSPORT | `resend` |
| RESEND_API_KEY | Sending API key restricted to the verified sender domain |
| SMTP_FROM | Plain verified sender email; both transports add the display name `Event Flow` |
| EMAIL_OUTBOX_ENABLED | `true`; `false` during recovery/reconciliation |
| MEDIA_STORAGE_ROOT | Absolute media directory on the persistent volume; image default: `/data/media` |
| GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET | Both configured for Google login, or both empty |
| RAILWAY_RUN_UID | `0` for the provisioning entry point; it immediately drops the server to UID/GID 1000 |
| PORT | Supplied by Railway; server binds `0.0.0.0` |
| NODE_ENV | `production` (image default) |

Use PostgreSQL 18 explicitly (`uuidv7()` is required). Keep its service private,
in the same environment/region. Never reset retained data or rewrite migration
history. Review migrations and backup before applying `pnpm db:deploy`; migration
failure must prevent rollout. Existing schema constraints and contracts remain.
Build uses nonsecret placeholder environment values only; real secrets are runtime
variables. `.dockerignore` excludes local environment, Git and generated artifacts.

The startup initializer uses `MEDIA_STORAGE_ROOT` (the image defaults to `/data/media`).
The path must be absolute and normalized, and all parent directories must already
exist. It checks the complete parent chain for root ownership, safe modes and
absence of symlinks or extended ACLs, then creates a missing 0700 media directory
and gives it to UID 1000. Configure the persistent volume mount to contain this
directory; setting the environment variable does not attach a volume.
Existing directories must already meet ownership/mode requirements. It refuses
symlinks or unsafe existing permissions rather than repairing them recursively.
The original media adapter still checks the complete path and files. On imported
volumes, provision correct owners and exclude extended ACLs on all files before
startup. Never expose the mount through a static web server. Run the existing
cleanup command in the running container as UID 1000, against the paired database.

Resend Free needs an owned, verified sending domain with the provider's DNS records;
the free Railway application domain cannot be used as your verified email domain.
No domain purchase is performed here. Disable click/open tracking, use a dedicated
API key/team budget and check current quotas before launch (Free advertises 100/day,
3,000/month). Auth verification and outbox share the quota and process pacing.
A quota exhaustion can delay mail until reset; inspect FAILED/PENDING delivery state.
Retries remain at least once; Resend idempotency is a 24-hour, identical-content aid.
No automatic replay of terminal failures is added.

Configure Google authorized JavaScript origin to the canonical HTTPS origin and
redirect URI to `<BETTER_AUTH_URL>/api/auth/callback/google`. Keep the existing
verified-email, explicit account-linking and no-implicit-merge behavior. Verify
real OAuth, verification email, Secure cookies and redirects after provisioning.
Canonical/public metadata and email URLs use BETTER_AUTH_URL, never the Host header.

Security acceptance: only `/ticket`, `/ticket/exchange` and credential-free
`/ticket/view/<ticketId>` requests may occur in the anonymous flow. Validate with
an artificial capability and inspect Railway edge logs without exporting secrets.
Do not open real legacy bearer paths on Railway. Keep tracing/body/header logging
and analytics disabled on private/auth flows. A fragment exchange requires JS;
invalid/expired sessions instruct users to reopen their private email link.

Enable backups for both PostgreSQL and the media volume, retain a portable copy
outside the project, and preserve auth/Ticket keys securely and separately. Define
acceptable loss and downtime, and rehearse restoration before launch. Database and
media snapshots are not atomic: restore all immutable files referenced by the
chosen database point. Keep recovery services private with EMAIL_OUTBOX_ENABLED=false
and no public auth traffic; reconcile potentially already-sent mail before enabling
dispatch. A restored old outbox can resend mail. Do not point a recovery clone at
live delivery credentials. Application rollback does not reverse migrations or
restore files; verify restored variables/keys/database targets explicitly.

Set Railway usage alerts and a spending limit suited to the account budget before
launch. Hobby includes a usage allowance, not an unlimited fixed-price deployment.
A hard limit can stop the service, including outbox and check-in; monitor usage,
volume space, database connections and mail quota. No purchase or limit is set by
this preparation. Healthchecks validate deployment readiness (DB SELECT 1 after
startup media validation); they are not continuous uptime monitoring.

Before production acceptance, verify deployed SSE heartbeat/reconnect, guest actions,
media upload/authorization, a volume-preserving redeploy, shutdown under delivery,
real Resend delivery and recovery. Local contract checks cannot establish these
external results. Platform references: [HTTP logs](https://docs.railway.com/cli/logs),
[volumes](https://docs.railway.com/volumes/reference),
[draining](https://docs.railway.com/deployments/deployment-teardown),
[Resend limits](https://resend.com/docs/api-reference/rate-limit),
[idempotency](https://resend.com/docs/dashboard/emails/idempotency-keys).
